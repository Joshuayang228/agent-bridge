# Security Checklist

## 使用场景

涉及安全、密钥、鉴权、远程接入、命令执行、路径、数据库输入时参考本文档。

> 本项目是「手机远程操控 agent」的通道 —— 一旦对外开放接入口，就是实打实的攻击面。
> 安全不是附加项，是这个产品能不能成立的前提。

## 密钥管理

- [ ] API Key、密码、token 全部走环境变量或安全存储。
- [ ] `.env` 文件在 `.gitignore` 中。
- [ ] 代码中无硬编码密钥或凭据。
- [ ] 长期凭据（配对 token、会话密钥）加密落盘，不明文存储。

## 远程通道鉴权（本项目核心）

- [ ] 手机端与 agent 端建立连接前必须**配对鉴权**，不允许匿名接入。
- [ ] 每条来自远端的指令都要校验身份，不能只在握手时验一次。
- [ ] 配对凭据可吊销 / 可轮换，丢手机后能远程踢下线。
- [ ] 传输层加密（TLS / wss），禁止明文传输指令和结果。
- [ ] 对外暴露的接口（HTTP / Webhook / 长连接）默认拒绝，白名单放行。

## 输入校验

- [ ] 所有外部输入有类型校验（远端来的指令尤其要当不可信数据处理）。
- [ ] 文件路径操作有防路径穿越检查。
- [ ] SQL 查询使用参数化，禁止拼接用户输入。
- [ ] 构造 shell 命令时对参数做转义 / 用数组式传参，防命令注入。

## 错误信息

- [ ] 对外错误响应只包含用户友好信息。
- [ ] 不暴露堆栈、内部路径、SQL 语句。
- [ ] 内部日志可保留必要诊断信息，但密钥脱敏。

## 危险操作确认（手机端人类监督）

远程 agent 能跑 shell、改文件，破坏性动作必须由人在手机上拍板：

| 动作类型 | 处理 |
|---|---|
| 只读操作（读文件、查状态） | 可自动执行 |
| 写操作（改文件、装依赖） | 按策略确认 |
| 破坏性操作（删除、`rm`、`kill`、`sudo`） | **必须手机端确认后才执行** |

## 命令安全分级

- safe：`ls` / `cat` / `echo` / `pwd` / `git status` 等只读命令。
- dangerous：`rm` / `chmod` / `kill` / `sudo` / `curl | sh` 等。
- unknown：未匹配命令，默认按最严格策略处理（ask 或拒绝）。

## 路径守卫

- 检查命令目标路径是否在授权工作区内。
- 保护系统关键路径，例如 `/etc`、`C:\Windows`、`~/.ssh`。

## 权限规则模型

责任链兜底 ask：

1. 自定义规则：用户定义的 regex pattern 与 allow/deny/ask。
2. 审批记录：历史已审批的命令或工具。
3. 命令分级：白名单和黑名单。
4. 默认策略：兜底 ask。

```ts
interface PermissionRule {
  type: 'command' | 'tool' | 'path'
  pattern: string
  action: 'allow' | 'deny' | 'ask'
  reason?: string
}
```

## 数据保护

- [ ] 敏感数据本地存储，不擅自上传云端。
- [ ] 依赖版本锁定，保留 lockfile。
- [ ] 新增依赖确认来源可信，警惕 typosquatting。
